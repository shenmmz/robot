## 一、当前 SERVO 指令的实现问题

参考 `servo.rbt`：
```
SERVO(0, 10, 10)     ← 单舵机
SERVO(1, 20, 10)     ← 单舵机
...
SERVO_S(0=90:30,1=90:30,...)   ← 多舵机联动
```

### 1.1 历史问题（已修复）

`TaskExecutor::executeCommand`（`src/logic/TaskExecutor.cpp:581-615`）早期是"非阻塞"模式——`setAngleWithSpeed` 只是把目标值塞进 `ServoController`，定时器在后台慢慢爬坡，`executeCommand` 立刻 `return true`，于是 `QTimer::singleShot(0, executeNext)` 立刻执行下一条。

这导致 `SERVO(0,10,10)` 后面的 `SERVO(1,20,10)` 是在 0 号舵机还没转到位时就发了指令——6 个舵机被一连串的 SERVO 指令互相"覆盖"，最终位置由最后一条 SERVO 决定。

**2026-06-15 修复**：SERVO 分支已调用 `waitForServoIdle(servo, cmd.servoChannels, 5000)`，确保每个通道到位后再返回。

### 1.2 当前速度控制实现（2026-06-15 二次优化）

> **设计动机**：旧版 50ms tick 软插值让舵机按 `:spd` 平滑移动，但 14 次同步 ZMC RPC 把 50ms 定时器实际拖慢到 ~200ms，导致 0.5° 阶梯抖动（"一卡一卡"）。修复一（2026-06-15）改用单帧直发，速度参数被完全忽略。

当前 `ServoController::setAngleWithSpeed` / `setAnglesForScript`（`src/hardware/ServoController.cpp:178-244`、`src/hardware/ServoController.cpp:269-...`）采用**阈值分流 + 100ms tick 软插值**：

| 输入 | 行为 |
|---|---|
| `\|Δ\|` ≤ 30°（`SHORT_MOVE_THRESHOLD_DEG`） | 单帧直发；`isMoving=false`；`waitForServoIdle` 立即返回 |
| `\|Δ\|` > 30° | 启动 100ms tick 软插值；`stepPerTick = delta / totalTicks`；`isMoving=true`；`waitForServoIdle` 阻塞到完成 |

**速度范围**（用户确认）：1-360°/s（`MIN_SCRIPT_SPEED` / `MAX_SCRIPT_SPEED`）。
**最大插值 ticks**：`MAX_INTERP_TICKS = 100`（10 秒封顶）。
**RPC 延迟容忍**：依赖 `Rs485Controller::m_cachedRegs` diff 缓存，命中后单路变更 14-28ms ≪ 100ms tick，平滑无抖动。

**多路并发**：`setAnglesForScript` 把每个目标通道按 \|Δ\| 决定走短距离单帧还是长距离软插值；长距离通道**共享一个 100ms QTimer**，每 tick 用 `setAllPwm` 同帧下发 6 路中间角度（diff 缓存），所有通道都到位后各自 `emit moveCompleted` 并 deleteLater timer。

**取消机制**：`ServoController::cancelAllMovements()` 停止所有活跃 timer，将各通道 `isMoving` 复位为 false；`TaskExecutor::stop()` / `pause()` 路径已接入该调用，保证 STOP/PAUSE 后 `waitForServoIdle` 立即返回。

## 二、需求拆解与建议方案

### 1. SERVO 单舵机：必须"等到位"才执行下一条

`ServoController` 已经有接口可以判断到位（`ServoController.cpp:354-370` 的 `onTimerTick`，`isMoving()` `ServoController.h:89`）：

- `m_states[ch].isMoving` 标志位
- `moveCompleted(ch, angle)` 信号

**建议**：单条 SERVO 指令改为**阻塞到位**。

```cpp
case ScriptCmdType::ServoMove: {
    servo->setAngleWithSpeed(ch, ang, spd);
    // 等待该通道 isMoving == false 或超时
    const int timeoutMs = 30000;
    QElapsedTimer t; t.start();
    while (servo->isMoving(ch)) {
        if (m_state != Running) return false;       // 支持暂停
        if (t.elapsed() > timeoutMs) {
            emit consoleOutput("[WARN] SERVO 超时未到位");
            break;
        }
        QThread::msleep(20);
        QCoreApplication::processEvents();
    }
    emit consoleOutput("[SERVO] PWM%1 已到位".arg(ch+1));
    return true;
}
```

### 2. SERVO_S 多舵机：同时下发，等"最慢的"到位

`SERVO_S(...)` 的本质是 6 个舵机一起动，按各自速度到位，最后一条指令完成后才继续。

**建议**：维护一个"目标通道集合"，在定时器中持续检查 `servo->isMoving(ch)`，当所有目标通道都到位或超时再继续。

可选两种实现：

- **A. 在 executeCommand 内忙等（与 SERVO 类似）**
  ```cpp
  QList<int> channels = cmd.servoChannels;
  // 等所有 isMoving == false
  while (std::any_of(channels, [](int ch){ return servo->isMoving(ch); })) { ... }
  ```
  简单直接，与 SERVO 保持一致。

- **B. 用 moveCompleted 信号计数**（更优雅，但要小心生命周期）
  ```cpp
  QAtomicInt remaining = channels.size();
  auto conn = connect(servo, &ServoController::moveCompleted,
                      this, [&remaining](int, float){ remaining--; });
  // 然后 QEventLoop 等 remaining==0
  ```
  A 更简单，建议先用 A。

### 3. 行号/光标绿色小点（执行进度指示）

当前执行进度用控制台滚动文本，**没有 UI 上的"行指示"**。

**建议两种实现**（任选其一，**先做轻量方案**）：

- **A. 在 QPlainTextEdit 的行号区画绿色圆点**（推荐）
  - 已经有 `CodeEditor`（或 `QPlainTextEdit`）继承思路（在 `编程页实现笔记.md:205` 提到过）
  - 通过 `QPlainTextEdit::extraSelections()` 给当前执行行加高亮
  - 同时在行号区（左侧）画一个绿色实心圆点

- **B. 在每条指令前加一个状态图标（QPlainTextEdit 不支持）**
  - 需要重写为 `QWidget` + 多行 `QLabel`，改动较大
  - **不推荐**

**实现要点**：

```cpp
// TaskExecutor 在 executeNext 开头发出 currentLine 信号
emit currentLineChanged(m_currentIdx);

// UiController 连接这个信号
connect(m_taskExecutor, &TaskExecutor::currentLineChanged, this, [this](int line){
    QTextEdit::ExtraSelection sel;
    sel.format.setBackground(QColor(0, 200, 0, 60));  // 浅绿高亮
    sel.format.setProperty(QTextFormat::FullWidthSelection, true);
    QTextCursor c = editor->textCursor();
    c.movePosition(QTextCursor::Start);
    c.movePosition(QTextCursor::Down, QTextCursor::MoveAnchor, line);
    c.select(QTextCursor::LineUnderCursor);
    sel.cursor = c;

    QList<QTextEdit::ExtraSelection> extra;
    extra << sel;
    editor->setExtraSelections(extra);
});
```

外加一个状态列（在行号前面或后面）画一个圆点：当行执行时 = 🟢，已执行 = ⚪，未执行 = ⚫。

### 4. 是否新增"等待舵机到位"指令？

**结论：建议**先**只在内部处理**（不新增指令），原因：

- `SERVO(ch, ang, spd)` 自身语义就是"转过去等到位"，是自然行为
- 多一条 `WAIT_SERVO()` 反而让用户困惑："我 SERVO 完要不要跟 WAIT？"

但如果你希望**灵活**（如"先一起启动，N 秒后无论是否到位都继续"），可加一个**可选超时参数**：

```
SERVO(0, 10, 10, timeout=2000)   ← 2秒内不到位就放弃
```

这能在脚本层面控制，不引入新指令。

如果后续要排查"批量 SERVO_S 起动后需要等外部条件"，那时再加 `WAIT_SERVO(timeout=5000)` 也不迟。

**待你决定**：
- 选项 1：内部处理，SERVO 自动等到位（推荐先做）
- 选项 2：内部处理 + SERVO 增加可选 timeout 参数
- 选项 3：新增 `WAIT_SERVO([ch, ...], timeout)` 指令

### 5. 点动按钮：按住连续加减

当前所有点动按钮都是 `clicked` 信号触发，**只触发一次**（按一下 = 加/减一次步长）。

**问题**：用户希望"按住 = 持续移动，松开 = 停止"。

**建议**：在 UiController 加一个通用的"按住自动重复"工具类（或方法），覆盖 3 类点动按钮：

| 类别 | 按钮 | 行为 |
|---|---|---|
| 关节 | `btnJogJ0M`/`btnJogJ0P` ... `btnJogJ5M`/`btnJogJ5P` | 按住 → 持续 jogJoint；松开 → stopMotion |
| 笛卡尔 | `btnJogXM/XP/Y/Z/Rx/Ry/Rz` | 按住 → 持续 jogCart；松开 → stopMotion |
| 舵机 | 手动调试面板的舵机 ± | 按住 → 角度持续加减；松开 → 停止 |

**实现思路**：

```cpp
// UiController 通用方法
template <typename OnTick, typename OnStop>
void bindHoldButton(QPushButton* btn, OnTick onTick, OnStop onStop) {
    auto* timer = new QTimer(this);
    timer->setInterval(50);  // 20Hz
    btn->setAutoRepeat(false);  // 关闭 Qt 自带 autoRepeat，用我们自己的
    connect(btn, &QPushButton::pressed, this, [=]{
        onTick();             // 立即触发一次
        timer->start();
    });
    connect(btn, &QPushButton::released, this, [=]{
        timer->stop();
        onStop();
    });
}
```

调用示例（关节点动）：

```cpp
bindHoldButton(btnJogJ0P,
    [this, axis=0] { onJogJoint(axis, true);  },  // 每 50ms 触发
    [this]          { m_robotController->stopMotion(); }
);
```

**注意**：
- 关节/笛卡尔"点动一次"是绝对移动到目标点，连续按就要**改用"相对步长"**：每 50ms 在当前 DPOS 上加/减一个步长
- 舵机的"按住"就是 `setAngleWithSpeed` 调一次（内部已经按速度平滑）
- 首次按下时立即执行一次（避免按下后等 50ms 才开始有反应）

**待你决定**：
- 步长来源：使用现有的 `spinManualJ` 步长字段（一个 spinBox 控所有轴）；还是为每轴独立步长？
- 加减速：连续点动时是否需要 ramp？（建议先不加，用固定速度）

## 六、2026-06-16 追加：SERVO 时间模式（T<ms>）

### 6.1 需求背景

参考 Gihand-KPZ32 出厂程序的舵机协议 `KPZ32出厂代码右/Gihand-KPZ32出厂程序/src/z_main.c`：

```
#005P1500T2000!    ← 通道 5，PWM=1500（90°），用 2000ms（2 秒）完成
```

KPZ32 单片机内部把 `T<ms>` 作为协议字段直接传给 STM32，`TIM2_IRQHandler`（20ms tick）每 20ms 累加一次 `cur += inc`，实现"时间控制"。

而本项目 R06 的舵机协议栈是 **QD-6PWM-V2.0 Modbus RTU**（参考 `docs/新6路PWM输出规格书/`），**物理层协议帧只有"频率+占空比"，没有 time 字段**。所以 SERVO 之前只能传"速度（°/s）"。

### 6.2 解决方案（2026-06-16 实施）

仿 KPZ32 的语义，在脚本层增加"时间模式"语法，物理层仍由 Qt 上层用 QTimer 100ms tick 软插值模拟时间控制：

| 语法 | 含义 | 行为 |
|---|---|---|
| `SERVO(0=90:30)` | 速度模式（°/s） | 与旧版一致，durationSec = \|Δ\| / spd |
| `SERVO(0=90:T2000)` | 时间模式（ms） | totalTicks = Tms / 100，stepPerTick = Δ / totalTicks |
| `SERVO(0=90:T0)` | 时间模式 = 0 | 单帧直发（瞬时到位） |
| `SERVO(0=90:T10)` | 时间模式 < 20 | 单帧直发（对齐 KPZ32 `T<20` 行为） |
| `SERVO(0=90:T2000,1=45:60)` | 混合模式 | 第 1 路时间、第 2 路速度（多路可独立） |

### 6.3 实现要点

**新增/修改**：
- `ScriptCommand.h`：增加 `QList<int> servoTimes` 字段（0 表示走速度分支）
- `UiController.cpp::parseScript`：识别 `T<ms>` 前缀（大小写不敏感）
- `ServoController.h`：增加 `setAnglesForScriptMixed(channels, angles, speeds, times)` 接口
- `ServoController.cpp`：实现混合分支；公式与 KPZ32 `inc = Δ / (time/20)` 思路一致（区别是 100ms tick）
- `ServoController.cpp::MAX_INTERP_TICKS`：由 100 放宽到 300（最长 30 秒）
- `TaskExecutor.cpp::executeCommand`：检测 `servoTimes` 中是否 > 0，自动走混合分支
- `UiController.cpp::onProgInsertServo`：弹窗增加"速度/时间"模式选择

**兼容性**：
- 旧脚本 `SERVO(0=90:30)` 完全兼容（速度模式）
- UI 拖拽仍走 `setAngleDrag`（默认 10°/s 慢爬升，不变）
- 单路/多路 SERVO 语法不变，只是每路参数支持 `:T<ms>` 替代 `:<spd>`

### 6.4 与 KPZ32 的差异

| 维度 | KPZ32 单片机 | R06 Qt 项目（2026-06-16 后） |
|---|---|---|
| 协议帧是否携带 time | 是（`#xxxPxxTxx!`） | 否（QD-6PWM 协议无此字段） |
| 时间插值 tick 周期 | 20ms（STM32 TIM2 中断） | 100ms（Qt QTimer，受 RPC 延迟影响） |
| 插值算法位置 | 单片机固件 | Qt 上层 |
| 时间上限 | 10000ms（4 位十进制） | 30000ms（`MAX_INTERP_TICKS=300` × 100ms） |
| 平滑度 | ★★★★★（单片机硬件级） | ★★★★（依赖 diff 缓存，14-50ms RPC） |

**结论**：R06 的"时间模式"是 KPZ32 语义在 Qt 上层的复刻，性能与"速度模式"等价（同一套 100ms tick 软插值机制），只是**用户能用"时间"参数表达意图**。物理层仍是 QD-6PWM 瞬时到位。

### 6.6 决策记录

- **语法风格**：选 `T<ms>` 前缀（与 KPZ32 出厂协议一致，用户更易理解）
- **时间上限**：从 100（10 秒）放宽到 300（30 秒）
- **MOVEJ 是否同步改造**：本轮**只改 SERVO**，MOVEJ 的时间控制留待后续单独处理（涉及 ZMC 加减速曲线换算，复杂度更高）
