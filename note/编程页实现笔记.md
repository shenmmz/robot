## 二、核心设计决策

### 为什么用 `QList<ScriptCommand>` 替代旧的 `QList<QList<double>> + QList<bool>`

旧的 TaskExecutor 只有 moveJ/moveL 两种指令，用两个分离的 QList：
- `m_targets`: 存坐标
- `m_isJoint`: 存类型

所有运动参数（speed/accel/decel/timeout）是 TaskExecutor 的成员变量，全局统一，无法每条指令独立设置。

新的 ScriptCommand 一条指令一个结构体：

```cpp
struct ScriptCommand {
    ScriptCmdType type;      // 指令类型
    QList<double> targets;   // 坐标
    double speed, accel, decel;  // 每条指令独立的运动参数
    int timeoutMs;
    int ioIndex, ioValue;    // IO 指令专用
    int delayMs;             // Delay 专用
    QString printText;       // Print 专用
    QString callFile;        // Call 专用
    QString sourceLine;      // 原始行文本，调试用
};
```

好处：
- 一条指令自包含所有参数，互不干扰
- 脚本中 `MOVEJ(..., spd=40)` 和下一行 `MOVEL(..., spd=30)` 各自独立
- 扩展新指令只需加枚举值，不影响已有指令

## 三、执行流程

```
用户点 ▶ 运行
  → UiController::onProgRun()
    → parseScript(text)                 ← 逐行解析脚本
    → m_taskExecutor->setCommands(cmds)  ← 设置指令列表
    → m_taskExecutor->start()           ← 开始执行

TaskExecutor::executeNext()
  → 取 m_commands[m_currentIdx]
  → 发射 taskProgress(current, total)
  → executeCommand(cmd)
    ├─ MoveJ:     switchToJointMode → directMoveAbsolute(关节轴) → waitForAxesReachTarget
    ├─ MoveL:     switchToCartesianMode → 读虚拟轴DPOS算增量 → directMoveAbsolute → waitForAxesReachTarget
    ├─ WaitIdle:  waitForAxesIdle({0..5}, 30000)
    ├─ Delay:     QThread::msleep + processEvents（每 30ms 检查暂停）
    ├─ SetDO:     ZAux_Direct_SetOp → consoleOutput
    ├─ WaitDI:    轮询 getDI → 匹配或超时 → consoleOutput
    ├─ Home:      executeHoming → waitForAxesIdle(60000)
    ├─ Print:     emit consoleOutput → 写入控制台
    └─ Call:      读子脚本文件 → 逐行 parse → 递归 executeCommand
  → m_currentIdx++
  → QTimer::singleShot(0, executeNext)   ← 下一轮
```

## 四、指令按钮插入逻辑

| 按钮 | 行为 |
|---|---|
| **MOVEJ** | 读当前关节 DPOS + 设置页/调试面板默认 speed/accel/decel/timeout → 拼接 `MOVEJ({...}, spd=..., acc=..., dec=..., timeout=...)` → insertAtCursor |
| **MOVEL** | 读当前笛卡尔虚拟轴 DPOS → 同 MOVEJ |
| **HOME** | 直接插入 `HOME()` |
| **WAIT_IDLE** | 直接插入 `WAIT_IDLE()` |
| **DELAY** | QInputDialog 输入毫秒 → `DELAY(500)` |
| **SET_DO** | 输入 DO编号(0-19) + 值(0/1) → `SET_DO(3, 1)` |
| **WAIT_DI** | 输入 DI编号 + 期望值 + 超时 → `WAIT_DI(0, 1, 5000)` |
| **PRINT** | 输入文本 → `PRINT("到达点位A")` |
| **#注释** | 插入 `# ` 光标移到行尾等输入 |
| **CALL** | 文件对话框选择 .rbt → `CALL("sub_pick.rbt")` |

### 运动参数来源优先级

```
readDefaultMotionParams():
  1. 调试面板 debugSpeed/debugAccel/debugDecel（如果当前页在手动画且勾选了调试模式）
  2. 设置页 spinDefaultSpeed/spinDefaultAccel（全局默认值）
  3. 硬编码兜底: speed=25, accel=50, decel=60, timeout=10000
```

## 五、文件操作

| 按钮 | 行为 |
|---|---|
| **📂 加载** | QFileDialog 打开 .rbt/.txt → setPlainText → 更新标题栏文件名 |
| **📄 新建** | 确认未保存 → clear → 标题栏重置为"未命名.rbt" |
| **💾 保存** | 有路径→覆盖；无路径→另存为对话框（默认 .rbt） |

保存路径记录在 `m_currentScriptPath`，第二次保存直接覆盖不用再选路径。

## 六、脚本解析器 parseScript()

支持的语法：

```
MOVEJ({j0, j1, j2, j3, j4, j5}, spd=40, acc=50, dec=60, timeout=8000)
MOVEL({x, y, z, rx, ry, rz}, spd=30, acc=50, dec=60, timeout=8000)
WAIT_IDLE()
DELAY(500)
SET_DO(0, 1)
WAIT_DI(0, 1, 5000)
HOME()
PRINT("文本")
CALL("子脚本.rbt")
# 注释（跳过不执行）
```

参数解析使用正则 `(\w+)=([\d.]+)` 提取 key=value，支持任意顺序。

注释行（`#` 开头）和空行跳过。

## 七、暂停/恢复处理

暂停时：
1. `m_state = Paused`
2. `stopMotion()` → rapidStop(0)
3. `cancelWait()` → 中断正在执行的 waitForAxesReachTarget
4. `waitForAxesIdle({0..5}, 2000)` → 等轴完全停稳
5. emit taskPaused → 弹出对话框

恢复时：
1. 根据当前指令类型重同步 CONNFRAME
2. `m_state = Running`
3. `executeNext()` → 从同一指令重新开始

DELAY 指令执行期间每 30ms 检查 `m_state != Running`，暂停时安全退出。

## 八、控制台输出

```cpp
void appendConsole(const QString& text) {
    // 格式: [14:30:05] 内容
    auto* console = findChild<QPlainTextEdit*>("progConsoleOutput");
    QString ts = QDateTime::currentDateTime().toString("[HH:mm:ss] ");
    console->appendPlainText(ts + text);
}
```

输出示例：
```
[14:30:01] 解析完成，共 5 条指令
[14:30:03] [INFO] SET_DO 0 → 1
[14:30:06] [INFO] WAIT_DI 0 → 匹配 (120ms)
[14:30:08] [PRINT] 轨迹完成
```

运行前自动清空控制台。

## 九、CALL 指令实现

```
主脚本 → CALL("sub_pick.rbt")
  → 查找路径（三种尝试）:
     1. 文件名直接打开
     2. exe目录/config/scripts/ 下查找
     3. 相对路径
  → 读取文件内容
  → 逐行解析（内联简化版解析器）
  → 逐行 executeCommand
  → 全部完成后返回主脚本
```

子脚本解析不如主解析器完整（不支持 spd= 等参数解析），因为 CALL 的上下文已经确定了速度。后续可扩展。
