# Robot_R06 修改记录

## 2026-07-01

### 问题描述
执行 `script.rbt` 脚本时，每个 `MOVEL` 指令都报 "等待运动到位超时"。

### 根本原因
在 **CONNFRAME 模式**（逆解模式）下：
- 虚拟轴 (6-11) 接收运动指令，是主动轴
- 关节轴 (0-5) 由虚拟轴通过 DH 模型自动解算并联动驱动，是从动轴

原代码使用 `waitForAxesIdle(jointAxes)` 等待关节轴停止，但 `GetIfIdle` API 对从动轴的状态检测不准确，导致即使关节轴已到达目标位置，仍可能返回 "运动中" 状态，从而引发超时。

### 修改内容
**文件**: `src/logic/RobotController.cpp`

**位置**: `moveL` 函数（约第595-599行）

**修改前**:
```cpp
// 等待关节轴运动停止(CONNFRAME 模式下虚拟轴会先到位,关节轴后到位)
QList<int> jointAxes = m_config->getJointAxisList();
result = api->waitForAxesIdle(jointAxes, timeoutMs);
```

**修改后**:
```cpp
// 等待虚拟轴到达目标位置(CONNFRAME 模式下虚拟轴直接执行运动指令)
// 注意：不能使用关节轴的waitForAxesIdle，因为在CONNFRAME模式下关节轴是
// 由虚拟轴通过DH模型联动驱动的从动轴，GetIfIdle对从动轴的状态检测不准确
result = api->waitForAxesReachTarget(virtualAxes, dposTargets, timeoutMs, 0.5f);
```

### 修改原理
- `waitForAxesReachTarget` 通过轮询 `GetDpos`（实际位置）并与目标位置对比来判断运动是否完成
- 这种方式直接读取位置值，不依赖 IDLE 状态，更适合 CONNFRAME 联动模式
- 容差设置为 0.5mm，对于笛卡尔空间运动是合理的阈值

### 验证方法
重新编译运行程序，执行 `script.rbt` 脚本，观察是否还有 "等待运动到位超时" 的警告。
